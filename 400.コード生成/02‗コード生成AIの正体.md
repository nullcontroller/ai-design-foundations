# コード生成を数学的に捉える

## 目的

本メモは、コード生成を「自然言語をそのままコードに変える魔法」ではなく、
**制約付き確率最適化問題**として理解するための整理である。
対象は主に **LLMによるコード生成**である。

---

# 1. 結論

コード生成は本質的に次の問題として考えられる。
**最も確率の高いコードを選ぶ問題**

```
生成コード = 条件のもとで最も確率が高いコード
```

ここでの条件とは

- 入力要求（仕様・質問・修正依頼）
- 使用言語
- API
- 既存コード
- 実行環境
- 性能条件
- セキュリティ条件
- コーディング規約

などである。

つまりコード生成とは、
**制約条件の下で最も自然なコードを探索する問題**
である。

ただし実務では  
単に「もっとも自然なコード」を出すだけでは不十分である。

実際には次の複数の評価を同時に満たす必要がある。

- 仕様に合っているか
- 実行可能か
- テストに通るか
- 保守しやすいか

つまり実務のコード生成は、
**複数の評価基準を同時に満たす探索問題**に近い。

---

# 2. なぜコード生成は難しいのか

自然言語生成では多少「それっぽい」文章でも成立する。

しかしコードでは

- 構文エラー
- 型エラー
- API誤用
- 例外処理不足
- 計算量悪化
- 既存設計との不整合

などがあるとすぐに問題になる。

つまりコード生成では次の4条件を同時に満たす必要がある。

```
構文が正しい
かつ
意味が正しい
かつ
実行できる
かつ
既存設計と整合する
```

このためコード生成は**単なる文章生成より遥かに難しい。**

---

# 3. コード生成の構造

## 入力

実際のコード生成の入力は単一の文章ではない。

```
入力 = 要求 + 既存知識 + 実行環境 + 制約
```

具体的には

### 要求
- 仕様
- 修正依頼

### 既存知識
- 言語仕様
- ライブラリ仕様
- 既存コード

### 実行環境
- OS
- ランタイム
- 依存関係

### 制約
- 性能
- 保守性
- 禁止事項
- 命名規則

LLMはこの複合入力からコードを生成する。

---

# 4. 生成は一回では終わらない

実務ではコード生成は次のサイクルになる。

```
生成 → 確認 → 修正
```

つまり

```
コード生成
↓
エラー検出
↓
修正生成
```

という反復過程になる。

これは数学的には**誤差を修正しながら最適解に近づく探索**に近い。

---

# 5. コードの評価

良いコードは一つの基準では決まらない。

主に次の評価がある。

- 正しさ
- 可読性
- 性能
- 安全性
- 既存設計との整合性

これらはしばしば衝突する。

例

```
性能最適化
→ 可読性低下

安全性強化
→ コード量増加

汎用化
→ 局所最適崩壊
```

したがって

**最良コードは評価基準の重み付けによって変わる**

---

# 6. プロンプトの意味

プロンプトは魔法ではない。

役割は**生成されるコードの確率分布を制約で絞ること**である。

有効な制約の例

- 出力形式
- 使用言語
- 接続点
- テスト条件
- 禁止事項

つまり良いプロンプトとは**探索空間を適切に狭める制約**である。

---

# 7. なぜ hallucination が起こるのか

コード生成モデルは**真偽判定器ではない**

したがって

```
もっともそれらしいコード
```

が選ばれる。

それが正しいとは限らない。

つまり

```
モデル出力 ≠ 正しいコード
```

である。

そのため実務では必ず

- テスト
- 実行確認
- 静的解析
- 型検査

が必要になる。

---

# 8. 実務での正しい使い方

コード生成AIで重要なのは

**賢さではなく誤り確率**

である。

推奨手順

1. 要求を書く  
2. 制約を明確にする  
3. コード生成  
4. 前提確認  
5. テスト  
6. 修正  

つまり

```
LLM + 検証パイプライン
```

として扱う。

---

# 9. 良いコード生成とは

良いコードとは

```
構文が正しい
かつ
意味が正しい
かつ
制約を満たす
かつ
保守可能
```

ことである。

そのためコード生成は

- 確率モデル
- 制約プロンプト
- 検証

の三者で成立する。

---

# 10. 結論

コード生成の本質は

```
制約付き確率探索 + 検証
```

である。

したがって正しい態度は

- 魔法視しない
- 一発正解を期待しない
- 生成より検証
- 前提条件を確認する

ことである。

コード生成AIは

**プログラマの代替ではなく探索空間を高速に走査する補助知性**

として理解するのが最も正確である。
